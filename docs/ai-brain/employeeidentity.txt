Identity Architecture
IMPORTANT:
The employee's display name must NOT become the technical identity of the agent.
Use stable internal identifiers such as:
chief_of_staff
sales
estimating
project_operations
compliance
customer_success
or follow the existing CP360 ID/naming conventions if an Agent Registry already exists.
For example:
Avery = presentation identity
Chief of Staff = role/title
chief_of_staff = stable system identity
Do NOT create business logic such as:
if agent_name == "Avery"
Business logic must reference the stable agent/role ID.
This allows CP360 customers to rename their AI employees later without affecting:
SOPs
workflows
permissions
authority levels
audit history
integrations
tools
knowledge access
scheduled operations

Voice Experience
The same identities should carry into the CP360 two-way voice experience.
Users should be able to naturally say things such as:
“Ask Marcus what's happening tomorrow.”
“Have Natalie update the homeowner.”
“Ask Daniel to review this estimate.”
“What does Clara need for the inspection?”
“Ask Maya which leads need follow-up.”
“Avery, what needs my attention today?”
The Voice Operations Brain must resolve these names to the appropriate stable agent IDs and then invoke
the SAME SOPs, workflows, authority controls, tools, verification, and audit system defined in the frozen
CP360 architecture.
Do NOT create separate voice agents.
Audit
Every AI Employee action must record the stable agent identity.
